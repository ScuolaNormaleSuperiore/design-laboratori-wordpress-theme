# ARCHITECTURE.md


## Architecture Notes

Design Laboratori Italia is a WordPress theme that behaves as a complete site once installed.
It provides custom post types (with ACF fields), configurable homepage sections, content import procedures, and custom templates for list/detail views.
Core runtime features include menu/taxonomy/page initialization and global search.


## Key Directories

- `inc/`: core classes and main modules.
- `template-parts/`: reusable template partials.
- `page-templates/`: archive/list templates for custom content types.
- `assets/`: styles, scripts, icons, images, Bootstrap Italia assets.
- `DOC/`: project documentation and schemes.
- `SETUP/`: ACF exports, Docker setup, and setup utilities.
- `SETUP/npm_scripts/`: project JavaScript scripts.
- `AGENTS/`: AI collaboration documentation.
- `.github/workflows/scorecard.yml`: GitHub Action settimanale che osserva la postura di sicurezza della supply chain del repository e pubblica il report in GitHub Code Scanning.
- `.github/workflows/ci.yml`: continuous integration (see *CI (GitHub Actions)* under *Quality checks*); `.github/scripts/` holds the scripts it calls.
- `tests/report/`: Report modules that produce results to read, without assertions (status, html, pa11y); `issues-report/` only stores issue snapshots.
- `tests/unit/`, `tests/bootstrap-unit.php`, `phpunit.xml`: PHPUnit unit tests (no WordPress). WordPress core stubs for PHPStan are supplied by the `php-stubs/wordpress-stubs` development dependency; `tests/phpstan/` holds local runtime and optional-plugin stubs.
- `tests/integration/`, `tests/bootstrap-integration.php`, `phpunit-integration.xml`: PHPUnit integration tests on a real WordPress with ACF and Polylang; its `support/` folder prepares the required plugins.
- `tests/e2e/`, `playwright.config.js`: Playwright functional tests on the dedicated Local site `dli-wp-e2e`, with a database baseline restored before and after each run.


## Main Files

- `functions.php`: theme bootstrap and runtime wiring entrypoint.
  - Loads configuration files: `config-lab.php`, `config-pages.php`, `config-menu.php`.
  - Loads wrappers/utilities/modules: `inc/wrappers-polylang.php`, `inc/wrappers-acf.php`, `inc/utils.php`, `inc/actions.php`, `inc/activation.php`.
  - Loads dependencies/admin tooling: `inc/theme-dependencies.php`, `inc/cmb2.php`, `inc/admin/options.php`.
  - Loads and instantiates runtime managers: `inc/classes/class-dli-contentsmanager.php` (with `class-dli-og-wrapper.php`, the Open Graph value object), `inc/classes/class-dli-labmanager.php` (`DLI_LabManager::plugin_setup()`).
- `config-lab.php`: theme constants.
- `config-menu.php`: default menu definitions.
- `config-pages.php`: default page definitions.
- `single-*.php`: detail templates for content types.
- `page.php`: standard page template.
- `search.php` and `index.php`: the two templates of the requests that the theme has no page for. `search.php` takes the native search of WordPress (`/?s=term`) to the search page of the theme (`page-templates/cerca.php`) in the language of the visitor, with the term in `searchstring`: the term is cleaned (`sanitize_text_field()`), cut at 100 characters and encoded, the address is built with `dli_get_search_link()` and sent with `wp_safe_redirect()`, so the redirect never leaves the site; the search page fills its field and runs the search only when the address carries the field `cercasito_nonce_field` that its own form sends (the field marks a submitted form: only its presence is checked, its value is not validated, since the search is read-only and its addresses can be shared), so the visitor presses the button once. The term is not unslashed again: WordPress has already removed the escaping of the request from `get_query_var( 's' )`. `index.php`, which WordPress requires in every theme, is the last fallback of the template hierarchy: it answers 404 with the 404 page of the theme (`$wp_query->set_404()`, `status_header( 404 )`, `get_template_part( '404' )`, as `category.php` does) and does not define `WP_USE_THEMES`, which WordPress has already defined before any template runs. Pages, posts, the content types, the archives and the 404 page have their own templates and never reach it; it is reached by the page of an attachment. Covered by `DLI_Search_Fallback_Integration_Test`.
- `inc/pwa.php`: PWA web app manifest — registers the `/manifest.json` virtual endpoint (same rewrite/query_vars/template_redirect pattern as the sitemap endpoints) and the related `<head>` tags (manifest link, theme-color, apple-touch-icon). No service worker.
- `inc/captcha.php`: optional Really Simple CAPTCHA integration — provides explicit CAPTCHA challenge data and validation helpers for the Contact and Newsletter templates. A challenge is used once: `dli_validate_captcha()` consumes it (`remove()`) after the check, also when the answer is wrong, so a right answer cannot be sent again and the same image cannot be tried twice (a prefix that is not made of letters, digits, hyphens and underscores, such as one with a dot or a slash, is refused before it reaches the plugin: the ones issued are digits). The page creates a new challenge at every load, so a refused form comes back with a new image.
- `inc/reserved-area.php`: the reserved area (single sign-on with WP SAML Auth, contents restricted by group with Groups; who sees a content is decided by Groups, not by the theme). It registers the tab **Configurazione → Area riservata** (box `dli_options_area_riservata`, option group `area_riservata` = `DLI_RESERVED_AREA_OPTION_KEY`) on `cmb2_admin_init` at priority 20, so it is the last tab, and only for the administrator (`manage_options`, like Indico, Iris and Altro). Fields: `reserved_area_enabled` ("Gestione area riservata", `'true'`/`'false'`, off by default), `reserved_area_page_id` (the public page "Area riservata", from `dli_get_pages_for_select()`) and `reserved_area_saml_only` ("Accesso solo tramite SAML", off by default). The two dependent fields carry the row class `dli-reserved-area-dependent`: `inc/admin-js/options.js` disables them while the main switch is No and enables them again just before the form is sent, so CMB2 does not save them empty (no file under `inc/vendor/` is touched). Readers: `dli_is_reserved_area_enabled()`, `dli_is_reserved_area_saml_only()` and `dli_get_reserved_area_page_id()`, which ignore the dependent settings while the main switch is off. `dli_promote_pending_user_on_group_join()` listens to the action `groups_created_user_group` of Groups (fired after a new membership is saved): with the reserved area on, a pending user who enters a group becomes a reserved area user (only that role is replaced; when the administrator gives the group from the profile of the user, Groups reports the membership during `edit_user_profile_update` and WordPress then saves the role that the form still shows, so the promotion is queued by `dli_reserved_area_promotion_queue()` and done by `dli_promote_pending_user_after_profile_save()` on `profile_update`, priority 999, after that save); the group `Registered`, which Groups gives to every new user, and a group that cannot be read do not promote. `dli_neutral_slug_for_saml_user()` (action `wp_saml_auth_new_user_authenticated` of WP SAML Auth, whatever the switch) sets `user_nicename` to `utente-<ID>`, since the username is the email and the slug is public (author address, REST). With the reserved area on, for both roles (`dli_user_has_reserved_area_role()`): `dli_reserved_area_login_redirect()` (`login_redirect`, priority 20, after the RelayState of WP SAML Auth at priority 1) sends a login whose destination is empty or in `wp-admin` to `dli_get_reserved_area_url()` (the chosen page in the current language, otherwise the home of the language), and keeps any other destination; `dli_redirect_reserved_area_users_from_admin()` runs on `init` (a user without capabilities is refused in `wp-admin/menu.php`, before `admin_init`) and sends an admin request away, except AJAX and `admin-post.php`; `show_admin_bar` is false. With "Accesso solo tramite SAML" too: `show_password_fields` and `allow_password_reset` are false, `wp_authenticate_user` answers the error `dli_reserved_area_saml_only` (WP SAML Auth does not run that filter, so the single sign-on is untouched), and `rest_request_before_callbacks` refuses with 403 a `password` sent to `/wp/v2/users/<id>`, `/me` or a new user with one of the roles (`rest_pre_insert_user` cannot refuse: the users controller does not check its result). `page.php` calls `dli_render_reserved_area_access()` before the content: on the chosen page or its translation (`dli_is_reserved_area_page()`) it prints `template-parts/common/reserved-area-access.php`, with the button "Accedi" (`dli_get_reserved_area_login_url()`: `wp_login_url()` back to the page, plus `action=wp-saml-auth` when WP SAML Auth is active, filter `dli_reserved_area_saml_available`) or "Sei collegato come…", the waiting message for a pending user and "Esci". Covered by `DLI_Reserved_Area_Integration_Test` and `DLI_Reserved_Area_Access_Integration_Test` (Groups and WP SAML Auth are not installed in the suite: the group lookup is a stand-in class declared by the test and the actions of the plugins are fired by hand).
- `inc/pagination.php`: pure helpers (no WordPress needed) that read the page size asked for in the address (`per_page`), which is input from the visitor: `dli_parse_positive_int()` accepts only digits (a sign, a decimal, an exponent, a list, a boolean or a number too large for an integer is not a number), `dli_clamp_per_page()` keeps a size up to the largest offered value (or the default, whichever is larger) and gives the default otherwise (used by `progetti.php`, `blog.php`, `luoghi.php`, `cerca.php` and `archive.php`, the template of the author and date archives: an old size in range keeps working), `dli_pick_per_page()` accepts only the offered values (used by `archive-progetti.php`, like the seven archives that already compared the value with the list). Callers pass `filter_input( INPUT_GET, 'per_page' )`, which is `false` for a list.
- `inc/detail-pages.php`: the rule for the detail pages that the editor has switched off. `dli_is_detail_page_disabled( $post )` is `true` for a person with `disattiva_pagina_dettaglio` on and for an event, a news item or a publication whose `link_dettaglio` is `sitoweb` or `allegato` (`DLI_ITEM_LINK`; empty or unknown is the detail page); a publication with a password is never switched off, and the direct link to the personal site (`abilita_link_diretto_pagina_persona`) does not close the page. `dli_block_disabled_detail_pages()` (`template_redirect`, priority 5, before the canonical redirect) answers 404 on a switched-off page of those types unless the user can `edit_post` it, so the editor can still fill it in. The same function empties the `link` of a person in the shared wrapper (`dli_from_post_to_wrapped_item()`, so the site search and the suggestions show the name without a link) and the link of the node in the site map (`dli_get_site_tree()`, whose XML sitemap skips a node without a link). `DLI_ContentsManager::main_search_query()` leaves out the people with `escludi_da_elenco` on. The filters of the content types of the search (`get_contenttypes_with_search_results()`) do not apply that exclusion yet. Covered by `DLI_Detail_Pages_Integration_Test`.
- `inc/menus.php`: helpers of the header menus — `dli_get_menu_dropdown_id()` (an identifier per dropdown, built on the menu, `main-nav` or `secondary-nav`, and the ID of the menu item), `dli_menu_item_has_address()`, `dli_get_menu_data_element()` and `dli_get_menu_item_data_element()` (the `data-element` of the links to people, projects, research and publications, from the page slug in Italian or English, else from the title). The markup of a first level item (link or dropdown) is in the partial `template-parts/header/menu-nav-item.php`, used by `DLI_Main_Menu_Walker` (`inc/walkers/class-dli-main-menu-walker.php`) and by `template-parts/header/secondary-menu.php`.
- `inc/cmb2.php`: loads CMB2 (`inc/vendor/CMB2`, version 2.13.5 since the theme 2.0.5, a copy that is replaced as a whole with the official package and never patched) and its addons, all with paths anchored on `__DIR__`, and wires the theme to it from outside. `dli_options_can_save_by_capability()` (filter `cmb2_can_save`) lets a user save an options page of the theme only when the user has the capability of the page (`dli_edit_site_configuration`, or `manage_options` for the reserved tabs Indico, Iris and Altro): CMB2 saves an options page through `admin-post.php` and checks only the nonce of the form, while the capability only shows the page in the menu. The boxes of posts, terms and users are not touched. The reserved tabs are also registered only for an administrator (`inc/admin/options.php`). Covered by `DLI_Options_Save_Permissions_Integration_Test`.
- `inc/search-autocomplete.php`: site search autocomplete — opt-in, disabled by default (*WP → Configurazione → Altro → Ricerca nel sito*). Registers the public `GET /wp-json/dli/v1/suggest` REST route (namespace `dli/v1`), cached in transients, and enqueues `assets/js/search-autocomplete.js` on the `page-templates/cerca.php` template. `setup_rest_api()` in `inc/classes/class-labmanager.php` carries an explicit exception so this route stays reachable even when the "Abilita REST API" option is off. The configuration of the script (`dli_search_autocomplete_config()`) carries the REST nonce for a logged-in user, which the script sends as `X-WP-Nonce`, so that the suggestions are the ones that user may read under a restriction plugin such as Groups; the transient cache is used only for visitors, never served to nor filled by a logged-in user. Covered by `DLI_Search_Autocomplete_Integration_Test`.
- `inc/admin/class-dli-csv-reader.php`, `inc/admin/class-dli-page-file-importer.php` and `inc/admin/class-dli-page-import-admin.php` are the CSV import of pages (Strumenti DLI → Importa → Pagine; it replaced the example pages tool of Utilità, which is removed). `DLI_CSV_Reader` is the common reader (HTTP origin, extension, 2 MB, MIME, BOM, separator `;` or `,` read from the header only, headers, rows with their physical numbers; no writes, errors as codes). `DLI_Page_File_Importer` holds the hierarchical parser (three levels in `level_1`..`level_3`, `menu_order`, the flags `promote_in_home` and `show_subpages_as_cards`, optional `page_key`, `excerpt` and `slug`), `plan()` (dry run, no writes) and `import()`; both validate the whole file before writing anything, and the limit is `MAX_PAGES` (200). Mode is «Solo nuove» only: the identity of a page is `(language, page_key)` or its normalized path, saved in the private meta `_dli_page_import_key`; an identity already imported is skipped, and an address used by a page without that meta (manual, draft, private, of the old example tool with `_dli_example_content`, or of another language) blocks everything and is never adopted, changed or deleted. The language is chosen in the form among the active Polylang ones; translations are linked only between rows with the same `page_key` in different languages, also from separate imports. The optional lorem ipsum (off by default, new pages only) takes 1 to 3 paragraphs of a private pool, chosen from the `page_key`. New pages are published, with the current user as author. `DLI_Page_Import_Admin` is the form (file, language, run mode — simulation by default —, Lorem box, confirmation box), the report and the downloads (the Italian and English examples and the model in `SETUP/CSV_Import/`, with a nonce); it needs `DLI_EDIT_CONFIG_PERMISSION` and `publish_pages` at every entry. The file is read again at every submit: no token, transient or lock is kept, so two people importing at the same moment could create duplicates. `DLI_Tools_Admin` only adds the «Pagine» tab and calls the module. Covered by `DLI_Csv_Reader_Unit_Test`, `DLI_Page_Import_Parser_Unit_Test`, `DLI_Page_Import_Lorem_Unit_Test`, `DLI_Example_Pages_Csv_Unit_Test`, `DLI_Page_File_Importer_Integration_Test`, `DLI_Page_Import_Admin_Integration_Test` and the E2E spec `pages-import-tool.spec.js`.
- `inc/home-sections.php`: pure helpers (no WordPress needed) of the homepage sections configured in Configurazione → Sezioni HP. `dli_normalize_hp_section_rows()` makes the saved rows safe: a row that is not an array, or without a section id, is left out; `enabled` and `show_title` are `true` only when saved as `true`; a `background` that is not `white` or `muted` is dropped; other properties are kept; every row carries `instance`, its position in the saved list. `DLI_ContentsManager::get_hp_section_options()` uses it and never writes the options back; `home.php` passes the whole row to the template part. `dli_get_hp_section_background_class( $args, $default )` gives ` section-muted` or nothing (the choice of the row wins, otherwise the default of the section); `dli_sanitize_hp_background()` is the server-side sanitization of the field "Sfondo sezione", shown only for the sections of the catalog (`DLI_HP_SECTIONS`) that have the key `background` (`DLI_ContentsManager::get_hp_sections_with_background()`; none yet). The admin of the page (`inc/admin-js/options.js`, `inc/admin-css/style-admin.css`) puts the up/down arrows that CMB2 creates for the sortable group in the header of each row and the name of the section in its title, using only the public events of CMB2 (`cmb2_add_row`, `cmb2_shift_rows_*`) and no file under `inc/vendor/`.
- `template-parts/home/hp-card-navigation-section.php` is the homepage section "Card di navigazione" (catalog id `card_navigation_section`, default background `muted`): it lists up to `max_items` published pages (the number chosen in the row of Sezioni HP, between `DLI_HP_ITEMS_MIN` and `DLI_HP_ITEMS_MAX`; `DLI_HP_CARD_NAVIGATION_DEFAULT_ITEMS` (6) when not chosen; the field "Numero massimo di elementi" is shown for the sections of the catalog with the key `max_items`, see `DLI_ContentsManager::get_hp_sections_with_max_items()`, and is checked by `dli_normalize_hp_max_items()` and `dli_sanitize_hp_max_items()`)  of the current language with the field `promuovi_in_home` on, ordered by `menu_order` (the field "Ordine" of the page) and then by title, with `dli_get_promoted_page_cards()`; protected pages are left out before counting and nothing is printed when no page is promoted. Only the pages of the chosen level are listed: the row has the field "Livello delle pagine" (`max_level`, a `select` shown for the sections of the catalog with the key `max_level`, see `DLI_ContentsManager::get_hp_sections_with_max_level()`), where 1 is the first level only (the default, `DLI_HP_CARD_NAVIGATION_DEFAULT_LEVEL`), 2 and 3 are up to that level and 0 is all the levels (`DLI_HP_PAGE_LEVELS`). The level of a page is its depth in the tree, 1 for a page without a parent; `dli_normalize_hp_page_level()` and `dli_sanitize_hp_page_level()` check the value and anything else means the default. `dli_get_promoted_page_cards( $limit, $max_level )` applies the level first (`post_parent` 0 for the first level, the count of the ancestors for the deeper ones) and the limit after it, so a promoted subpage never takes the place of a first level page and is not a card by default (it is a group of "Navigazione per pagine" when it has subpages). Each page is a `template-parts/common/card-nav.php` card in a column chosen by `dli_get_hp_navigation_column_class()` (the last row is centered). Title and subtitle come from Layout HP (`home_card_navigation_title`, `home_card_navigation_text` and their `_eng` versions); identifiers use the position of the row (`blocco-card-navigation-<instance>`).
- `template-parts/home/hp-page-navigation-section.php` is the homepage section "Navigazione per pagine" (catalog id `page_navigation_section`, default background `muted`): the groups are the published pages of the current language with the field `promuovi_in_home` on that have published subpages (`dli_get_promoted_page_groups( $max_groups, $max_items )` in `inc/pages.php`; the same shared flag as "Card di navigazione"); groups and subpages are ordered by `menu_order` and then by title, the limits are applied after that, protected and draft pages are left out before counting, and the menus of the site are not read. The numbers come from the row of Sezioni HP (`max_items` groups, `max_subitems` per group, between `DLI_HP_ITEMS_MIN` and `DLI_HP_ITEMS_MAX`; defaults `DLI_HP_PAGE_NAVIGATION_DEFAULT_ITEMS` and `DLI_HP_PAGE_NAVIGATION_DEFAULT_SUBITEMS`, 4 each; see `DLI_ContentsManager::get_hp_sections_with_max_subitems()`). The title of a group is plain text. The same list of links (`template-parts/common/page-link-list.php`) is printed in columns (`d-none d-md-flex`, class from `dli_get_hp_groups_column_class()`) and in an accordion (`d-md-none`, first panel open); the identifiers use the position of the row and the page of the group (`blocco-page-navigation-<instance>`, `page-navigation-<instance>-accordion`, `-head-`, `-body-`, `-title-<page>`). Title and subtitle: Layout HP (`home_page_navigation_title`, `home_page_navigation_text` and their `_eng` versions).
- `template-parts/home/hp-page-index-section.php` is the homepage section "Indice di una pagina" (catalog id `page_index_section`, default background `white`): the index of a page chosen **in the row** of Sezioni HP (field `page_id`, a `select` shown for the sections of the catalog with the key `page_id`, see `DLI_ContentsManager::get_hp_sections_with_page_id()`, checked by `dli_sanitize_hp_page_id()` and kept as an integer by `dli_normalize_hp_section_rows()`; there are no fields in Layout HP). `dli_get_page_index()` in `inc/pages.php` shows the page in the current language (`dli_get_page_in_current_language()`: a draft, a protected page, a page that is gone or has no translation gives nothing) and gives its published subpages without a password that have subpages of their own as columns (`dli_get_page_link_group()`, shared with `dli_get_promoted_page_groups()`) and their subpages as links; a subpage without children is not a column and, without columns, nothing is printed. The title is the title of the page and is always the `h2` of the section, which names it (`aria-labelledby`) and comes before the `h3` of the columns: it is seen only when the row asks for it and otherwise `visually-hidden`, so that the headings never skip a level. The links of the list are not underlined at rest and are underlined on hover and focus, like in the playground: one rule in `assets/css/main.css` for the three sections that print the list of page links (classes `page-index-section`, `page-navigation-section` and `tabs-section`). The row of Sezioni HP shows the chosen page after the name of the section in its closed title (`Sezione 3 (Indice di una pagina — Ricerca)`, from `dliShowRowLabels()` in `inc/admin-js/options.js`, which listens to the select of the page too), so that several indexes in the same home can be told apart; the two numbers of the row have a description that says what they count for each section (cards, groups, columns, links). The row chooses the most columns (`max_items`, `DLI_HP_PAGE_INDEX_DEFAULT_ITEMS` = 4) and links per column (`max_subitems`, `DLI_HP_PAGE_INDEX_DEFAULT_SUBITEMS` = 6). The columns (tablet and desktop) and the accordion (phone, first panel open) are printed by `template-parts/common/page-groups.php`, shared with "Navigazione per pagine" (`prefix` `page-index` or `page-navigation`): identifiers are `blocco-page-index-<instance>`, `page-index-<instance>-accordion`, `-title-<page>`, `-head-<page>`, `-body-<page>`, so two copies never share one, also for the same page. The choices of the field are the pages of the default language (`dli_get_index_pages_for_select()`: `dli_get_pages_for_select()` plus the pages already chosen in a row that can no longer be shown, labelled "(non visibile)", added by `dli_add_chosen_pages_to_select()`, which the tabs use too; the pages are looked for in every language, `lang` empty, so that the filter of Polylang by the language of the screen never hides a page already chosen).
- `template-parts/home/hp-tabs-section.php` is the homepage section "Pannello tab" (catalog id `tabs_section`, default background `white`): the Tabs component of Bootstrap Italia with no script of the theme (arrows move the focus, Enter or Space open the panel; the first tab is the open one). The tabs are **one global set**, the repeatable group `home_tabs_items` of Layout HP (`etichetta`, `etichetta_eng`, `descrizione`, `descrizione_eng`, `pagine`), and every copy of the section shows the same set; title and subtitle are `home_tabs_title` and `home_tabs_text` and their `_eng` versions. `inc/home-tabs.php` reads it: `dli_get_home_tabs()` normalizes the rows (`dli_normalize_hp_tab_rows()`), keeps the tabs of the current language (`dli_get_hp_tabs_for_language()`: the label makes a tab, a tab without text and without pages is left out, a missing English label or text is the Italian one, `dli_pick_lang_value()`) and resolves the linked pages with `dli_get_tab_pages()`; those helpers are pure (no WordPress needed) and live in `inc/home-sections.php`, together with `dli_is_blank_text()` and `dli_sanitize_hp_tab_page_ids()`. The linked pages are chosen from the published pages of the default language without a password, as a tree (`dli_get_pages_for_select()` in `inc/pages.php`; a page whose parent is not listed starts a subtree at the first level), plus the pages already chosen by a tab that can no longer be shown, labelled "(non visibile)", so that saving Layout HP does not drop the link (`dli_get_tab_pages_for_select()` in `inc/home-tabs.php`, the `options_cb` of the `pw_multiselect` field) and shown as their translation in the current language (`dli_get_page_in_current_language()`: published, type page, no password, translated, otherwise left out). The description is a WYSIWYG field cleaned with `wp_kses_post` both when it is saved (`sanitization_cb`) and when it is printed. Identifiers use the position of the row (`blocco-tabs-<instance>`, `tabs-<instance>-tab-<n>`, `tabs-<instance>-panel-<n>`), so the section can be repeated. In the admin, `inc/admin-js/options.js` gives the rows of `home_tabs_items` the arrows in the header and the label in the title (`Tab 1 (Etichetta)`, written again after every swap and every removal of a row, with the same helper `dliShowRowLabels()` as the sections), and forgets the cached `data('iterator')` of the two rows at `cmb2_shift_rows_start`: CMB2 2.11.0 changed only the attribute while its rich text editors are built again from the cached number, which put a description under the wrong tab after a second swap of rows added in the page (reproduced by `tests/e2e/specs/home-tabs.spec.js:224`). CMB2 2.13.5 sets `data('iterator')` itself, so the two lines look redundant, but they are **kept**: without them that test passed in 14 of 16 valid runs and failed once with an empty description (with them: 10 of 10); removing them needs more measurements.
- **Sections that can be repeated.** In Sezioni HP only a section of the catalog (`DLI_HP_SECTIONS`) with the key `repeatable` set to true can be in the home more than once: Indice di una pagina, Video and Banner, whose copies have their own data and identifiers. Every other section, and any section added to the catalog and not declared, is single (`DLI_ContentsManager::get_hp_sections_repeatable()` and `get_hp_sections_single()`). The server gives the list of the single ones to `inc/admin-js/options.js` (`window.dliHpSections.single`, `wp_localize_script` in `dli_enqueue_options_script_after_cmb2()`); the script (`dliLimitSectionChoices()`) disables, in the menu of each row, the options of the single sections that another row has chosen, never the one the row itself has chosen (a disabled option is not sent with the form, so a row saved before the rule with a single section twice would lose its value), and starts a new row from the first section still available. It is an aid of the interface only: the server does not drop or reject rows, and the home prints what is saved. Covered by `DLI_Homepage_Sections_Integration_Test`, `DLI_Options_Assets_Integration_Test` and the E2E spec `home-sections-admin.spec.js`.
- `template-parts/home/hp-video-section.php` is the homepage section "Video" (catalog id `video_section`, default background `muted`, keys `video_url` and `title`): **every row of Sezioni HP has its own video**. The row holds `video_url` (field "URL del video", `text_url`, sanitized by `dli_sanitize_hp_video_url()`: only an http or https address, anything else is nothing; the player is YouTube's), `title` and `title_eng` (plain text up to `DLI_HP_ROW_TITLE_MAX` = 120 characters, `dli_sanitize_hp_row_title()`) and the background. A row without an address prints nothing; the old option `home_page_video_url` of Layout HP is not read and its field is gone (the saved key stays in the options; there is no migration, the address is written again by hand in the row). The title is `dli_get_hp_row_title( $row, $is_italian )`: the one written in the language of the page and nothing else, so an English page without an English title has none, and the section has no default name; it is printed only when the row asks to show it, and then the section is named by it (`aria-labelledby`); when it is not printed there is no heading, hidden or not, and no `aria-label`. Identifiers use the position of the row (`blocco-video-<instance>`). The player is the shared component `template-parts/common/sezione-video.php`, also used by the detail pages of events, patents and spin-offs: without the optional argument `instance` it prints the identifiers it has always had (`vid1`, `chk-remember`, `transcription9`), with it every identifier carries it (`vid-<n>`, `chk-remember-<n>`), and the one function `window.dliLoadYouTubeVideo( playerId, url )` is defined once and called by each button with its own player (the old `const loadYouTubeVideo` stopped the second script of a page that had two videos). The closed row in the admin is named by the title in Italian or, without it, the code of the video (`dliVideoCode()` in `inc/admin-js/options.js`). Covered by `DLI_Home_Video_Integration_Test` and the E2E spec `home-video.spec.js`.
- `template-parts/home/hp-banners-section.php` and `inc/home-banners.php` are the homepage section "Banner" (catalog id `banners_section`, keys `max_items` = `DLI_HP_BANNERS_DEFAULT_ITEMS` (3), `banner_mode` and `title`): **every row of Sezioni HP chooses its banners**. `dli_get_home_banners( $row )` gives the banners: *automatic* (the default; also a row saved before the fields existed) is the published banners of the current language by the field `priorita`, as many as `max_items` of the row (1 to 12, 3 when empty); *manual* (`banner_mode` = `manual`, field "Come scegliere i banner") is the list `banner_ids` (field "Banner scelti", `pw_multiselect`, sanitized by `dli_sanitize_hp_id_list()`, which the tabs use too) in the order chosen, at most `DLI_HP_ITEMS_MAX`, ignoring `max_items`; each chosen banner (they are those of the default language, `dli_get_banners_for_select()`) is replaced by its translation in the current language through `dli_get_banner_id_in_current_language()`, and a banner that is a draft, trashed, missing, not a banner or without that translation is left out; a manual row with nothing chosen prints nothing. The same banner can be chosen in two rows. The select keeps a banner already chosen that can no longer be shown, marked "(non visibile)". The images are read with one query. The section is wrapped in `<section id="blocco-banner-<instance>">`; the markup of a banner is unchanged and its heading id carries the instance (`hero-school-title-<instance>-<banner>`). The title (`title`, `title_eng`) follows the same rule as the Video: written in the language of the page and asked by `show_title`, otherwise there is no heading at all, so a row without title looks as the banners always did. The closed row in the admin is named by the mode and, in the automatic one, the number. Covered by `DLI_Home_Banners_Integration_Test`.
- `template-parts/home/featured-contents.php` is the homepage section "Contenuti in evidenza" (catalog id `featured_contents`): up to three boxes, each with a content type and a title in Italian and English, configured in the three non-repeatable groups `featured_contents_<n>` of Layout HP (`featured_contents_type_box_<n>`, `featured_contents_label_box_<n>` and its `_eng` version; the old `featured_contents_template_box_<n>` is not read). `inc/featured-contents.php` reads them: `dli_get_featured_boxes()` takes each box through `dli_normalize_featured_box()` (pure, in `inc/home-sections.php`), leaves out a box whose type cannot be shown or that has no content, reads the contents of a type once (`dli_get_featured_posts()`: promoted, current language, `DLI_HP_FEATURED_ITEMS` = 3, newest first, `no_found_rows`) and gives each box its title (an empty one is the name of the type), renderer, listing address and button label. The types a box can show are `dli_get_featured_content_types()` (those with the field `promuovi_in_home`). The layout is decided by the type, not chosen (the news card has the category linked to the news page filtered by `cat` and then the date as day/month/year, `DLI_ACF_DATE_FORMAT`, for example 15/01/2026; the publication card of the box has `it-card border-bottom` with no shadow, like the playground, and the shared partial gets `compact` for the authors and `show_year` off, so the box shows no year while the list section and the archive keep it; the event card follows the playground: title, a body with the date and time and the place, a footer with the category linked to the events page filtered by `cat`; the place is the plain text field `luogo`): `dli_get_featured_renderer()` maps news, events and publications to `card-notizia.php`, `card-evento.php` and `card-pubblicazione.php` in `template-parts/home/featured-contents/` and any other type to `card-fallback.php` (title, image, abstract, link only); the partials receive the content already read and print only the `<article>`. The row is shared only among the boxes that have contents (`dli_get_featured_column_class()`: one box full width, two halves, three thirds). Headings: a visually hidden `h2` for the section, an `h3` for each box and an `h4` for each item. The title of an item leads where the editor chose (`dli_get_content_link()`, which `dli_get_publication_link()` now calls: detail page, external address or file; a protected content always leads to its own page; a choice without an address is plain text, never an empty `href`). The button leads to the listing page of the type (`dli_get_featured_archive_url()`: found by its Italian slug in `DLI_PAGE_PER_CT`, taken in the current language through its translation, only when published; otherwise there is no button). A section that is off prints nothing and queries nothing. The events are ordered by publication date, as before; the date of an event card is its own (`dli_get_event_datetime_display()`). The rule `ul.it-card-list.row` in `assets/css/main.css` keeps the cards aligned with the title of the box.
- `inc/pages.php`: helpers of the base pages. The queries that list pages to visitors (`dli_get_subpage_cards()`, `dli_get_promoted_page_cards()`, `dli_get_page_link_group()`, `dli_get_page_index()`, `dli_get_promoted_page_groups()`) pass `'suppress_filters' => false`, so that a restriction plugin such as Groups hides the pages the user may not read (`get_posts()` skips the query filters by default); the choices of the admin fields keep the default. Covered by `DLI_Restricted_Pages_Integration_Test`. Known limit: the categories cached by `dli_get_all_categories_by_ct()` and the years of `page-templates/pubblicazioni.php` are computed on all the contents, so a filter may offer a category or a year used only by restricted contents. `dli_get_subpage_cards()` returns the direct subpages that can be listed as navigation cards: published, in menu order, without the password-protected ones; the abstract is the page summary (`DLI_Page_Manager` enables the excerpt for pages) or the beginning of the text without tags, blocks and shortcodes, cut at `DLI_PAGE_CARD_EXCERPT_WORDS` (`config-lab.php`). `page.php` prints them before the text, under the visible title «In questa sezione» (`aria-labelledby`), with the partial `template-parts/common/card-nav.php`, only when the page has the `mostra_sottopagine_a_card` field on and is not locked by its own password. `DLI_Page_Manager` also defines `promuovi_in_home` (used by the home sections that list pages).
- `inc/publications.php`: helpers of the publications shared by the detail page, the archive and the home cards. `dli_get_publication_authors()` returns the authors that can be shown (published persons with a name, with the link to their page unless the detail page is disabled). `dli_get_publication_link()` is the single place that decides where the title of a publication leads (the `link_dettaglio` field, like events and news: `scheda` / `sitoweb` = the `url` field / `allegato`; a password-protected publication always leads to its detail page) and whether the address leaves the site; it relies on `dli_manage_item_link()` (`inc/utils.php`), which reads `url` for publications and `sitoweb` for events and news. The publication wrapper (`dli_from_publication_to_wrapped_item()`) carries `link` and `link_external` and has no description or content for a protected publication. The title is printed by the partial `template-parts/common/linked-title.php` (plain text when there is no address, never an empty `href`; a link that leaves the site opens in a new window and says so). The detail address (`/pubblicazione/<slug>/`) is registered by `DLI_Publication_Manager`, which rewrites the rewrite rules once per `REWRITE_RULES_VERSION` (option `dli_publication_rules_version`) so that a site updating the theme needs no manual permalink save.
- `phpcs.xml.dist`: PHP CodeSniffer rules.
- `package.json`: frontend/development tooling dependencies.
- `publiccode.yml`: public administration reuse catalog metadata.


## Content Model

All custom post types have `has_archive=false`: listings are WordPress pages
with a page template, resolved through `DLI_PAGE_PER_CT` and
`dli_get_template_page_url()`. Slugs are constants in `config-lab.php`. Each CPT
is registered by its manager in `inc/classes/` (CPT, taxonomy and ACF field
group together), instantiated by `DLI_LabManager::plugin_setup()`.

| Post type | Detail template | Listing template (`page-templates/`) |
|---|---|---|
| `persona`, `progetto`, `evento`, `notizia`, `brevetto`, `luogo`, `spinoff`, `risorsa-tecnica`, `indirizzo-di-ricerca` | `single-<slug>.php` | `persone`, `progetti`, `eventi`, `notizie`, `brevetti`, `luoghi`, `spinoff`, `risorse-tecniche`, `ricerca` |
| `pubblicazione` | `single-pubblicazione.php` | `pubblicazioni.php` |
| `banner`, `sponsor`, `tipologia-persona` | none (`public=false`) | none |

- Core `post` (blog) is extended by `Post_Manager`; core `page` by `DLI_Page_Manager`.
- Taxonomies: `struttura` (persona), `tipologia-luogo` (luogo), `tipo-pubblicazione`,
  `area-tematica` (brevetto), `settore-attivita` (spinoff), `tipo-risorsa-tecnica`.
  Events, news and posts use the core `category`. `HOLDER_TAXONOMY` is defined in
  `config-lab.php` but not registered.
- ACF field groups are defined in PHP (`acf_add_local_field_group()` in each
  manager). The JSON files in `SETUP/ACF_Custom_Fields/` are exports of those
  groups, used to import the fields again into ACF; the code does not load them.
  Every export must describe the same fields as the PHP group: when a group changes
  in PHP, update its export in the same change. `DLI_Acf_Exports_Integration_Test`
  compares every export with the registered group (properties of each field and of
  the group, missing and extra fields) and checks that every registered group has an
  export.
- Unified item shape for listings: `DLI_POST_WRAPPER` (`config-lab.php`).
- Place maps (`posizione_gps` in `class-placemanager.php`) use the ACF
  `open_street_map` field provided by ACF OpenStreetMap Field, with the `leaflet`
  return format. The unused CMB2 Leaflet Geocoder addon was removed in 2.0.5;
  it is not a dependency of these maps.


## Runtime Components (`inc/classes/`)

- `DLI_LabManager` (`class-dli-labmanager.php`): singleton; instantiates every manager
  and importer, sets languages, image sizes, upload limits and permalinks, filters
  REST access (`setup_rest_api`) and applies security tweaks (no generator, no XML-RPC).
- `DLI_AuthorizationManager` (`class-dli-authorizationmanager.php`): role `dli_super_editor` (Editor plus
  `edit_theme_options` and `dli_edit_site_configuration`) and role `dli_pending_user` ("Utente in attesa"):
  no capability at all, not even `read`, created only when missing and never rewritten, and assigned to
  nobody by the theme (for example the initial role of a user created by a single sign-on), and role
  `dli_reserved_area_user` ("Utente area riservata", `DLI_RESERVED_AREA_USER_ROLE_SLUG`): an approved user of
  the reserved area, whose only capability is the theme marker `dli_reserved_area_access`
  (`DLI_RESERVED_AREA_ACCESS_CAP`), which WordPress ignores (no dashboard, no profile); also created only when
  missing. Which of the two a new user gets is the WordPress setting *Ruolo predefinito del nuovo utente*.
  WordPress lets everybody edit the own profile, also through `POST /wp/v2/users/me`, so a `map_meta_cap` filter
  (`deny_profile_editing_to_pending_user()`) answers `do_not_allow` to `edit_user` for both roles
  (`DLI_AuthorizationManager::get_reserved_area_roles()`); an administrator still edits them.
  The admin bar, the redirect from `wp-admin`, the password rules and the promotion from the first role to the
  second are in `inc/reserved-area.php` and depend on Configurazione → Area riservata. Covered by
  `DLI_Pending_User_Role_Integration_Test` and `DLI_Reserved_Area_User_Role_Integration_Test`.
- `DLI_PolylangManager`: which post types and taxonomies Polylang translates.
- One manager per content type (events, news, patents, people, people types,
  places, projects, publications, research activities, spin-offs, sponsors,
  technical resources, banners, posts, pages).
- `DLI_ContentsManager`: static query helpers, site search, homepage section
  helpers, Open Graph data.
- Public email and PEC addresses are sanitized and obfuscated with
  `antispambot()` before template output; the people table omits email data
  entirely when its email column is disabled.
- `Newsletter_Manager`: Brevo newsletter subscription and validation.
- Importers: `DLI_BaseImporter` (abstract), `DLI_IndicoImporter` (events),
  `DLI_IrisPatentImporter` (patents); `inc/admin/class-dli-people-file-importer.php`
  is a separate CSV people import with dry-run; the CSV import of pages is described under Main Files.


## Conventions and Intentional Patterns

- Polylang wrappers (`inc/wrappers-polylang.php`): always call `dli_*` wrappers,
  never `pll_*` directly. Each is guarded by `function_exists()`; without Polylang
  readers fall back to `DLI_DEFAULT_LANGUAGE` and writers do nothing. The theme
  does not activate without Polylang.
- ACF wrappers (`inc/wrappers-acf.php`): use `dli_get_field()` / `dli_update_field()`.
- Options: `dli_get_option( $field, $option_key )` (CMB2 options page
  "Configurazione", base key `dli_options`); booleans are the strings `'true'` /
  `'false'`; `dli_get_option_by_lang()` appends `_eng` for non-Italian.
- Helpers in `inc/utils.php` are guarded by `function_exists()`; this is intentional.
- Class naming is mixed (`DLI_*Manager` and `Event_Manager`-style); follow the
  existing name in the file you edit.
- Italian is the default language; the English version is a separate
  Polylang-linked post.

  menu gets its items only when it is created. The default pages include "Area

## Quality checks

This is the canonical list of quality-check commands for AI agents. Run them
from the theme root. The human-facing `README.md` (*Sviluppo e verifiche*)
and `tests/README.md` describe the same checks for contributors. Checks come in
three families: static checks and tests (run with Composer) and Reports (run with npm).

- PHP lint (canonical): `composer run lint:php`. Automatic fixes, only when
  needed: `composer run lint:php:fix`. The commit gate also runs PHPCS on the staged PHP,
  CSS and SCSS files (`.githooks/check-staged-phpcs.sh`, errors only, staged content) and
  blocks the commit on any error, including errors that were already in the file.
- Static analysis: `composer run lint:phpstan` runs the whole theme at the required
  level 5, set in `phpstan.neon` (the only place where the level is written). It is also
  the commit gate: `.githooks/pre-commit` runs it through `.githooks/check-phpstan.sh` and
  blocks the commit on any error. `composer run lint:phpstan:level6` is the non-blocking
  whole-theme progress check toward level 6.
- Unit tests: `composer test:unit` (PHPUnit, no WordPress; also run by `.githooks/pre-commit`).
- Integration tests: `composer test:integration` (real WordPress, ACF and Polylang; database `dli_wordpress_test`; the first run downloads the plugins into the ignored `tests/integration/.cache/`; not run by the hook).
- E2E tests: `composer test:e2e` (also `test:e2e:headed` and `test:e2e:ui`; Playwright on the Local site `dli-wp-e2e`; needs `DLI_E2E_SITE_PATH`; restores the site to its baseline before and after the run; not run by the hook).
- Unit and integration tests together: `composer test:all` runs the unit and integration suites in this order and stops at the first one that fails; it needs the integration setup (not run by the hook). It does **not** run the E2E suite, which is long (about ten minutes): run it separately with `composer test:e2e`. `composer.json` sets `config.process-timeout` to 1200 seconds: Composer's default of 300 seconds stops the E2E suite as soon as it takes longer.
- Runtime scan: `npm run status:scan -- <baseUrl>` (HTTP, PHP and JavaScript
  errors, broken resources, timeouts). Requires Chromium, installed once with
  `npm run status:scan:install-browser`.
- Accessibility scan (WCAG 2 AA, desktop and 320 px): `npm run pa11y:scan -- <baseUrl>`.
- HTML validity: `npm run html:scan -- <baseUrl>`; requires Java 8+ on `PATH`.
- Dependency vulnerabilities: `composer audit` and `npm audit --omit=dev`.
- OpenSSF Scorecard runs remotely on GitHub after changes to the default branch, branch-protection changes and on a weekly schedule. It is observational: it does not run locally and does not block commits.
- `status` and `html` have a `*:gate` variant (exit code 1 on failure) and a
  `*:compare` variant (compares the two most recent reports); `pa11y:scan:gate`
  exits with code 2 when WCAG errors exceed the threshold. Options and report
  formats are documented in `tests/report/*/README.md`.


### CI (GitHub Actions)

`.github/workflows/ci.yml` is the source of truth of what runs; this table summarises it and
is updated in the same change that adds or alters a check. The CI is the safety net of the
`pre-commit` hook: the same checks on a clean machine, plus PHP 8.0 (the declared minimum), for
whoever has not activated the hooks and for pull requests. It is **observational**: a failure
turns the run red but blocks nothing, and the push is never refused. It runs on push to `dev`,
`main` and the prefixed branches (`features/**`, `bugfix/**`, `refactor/**`, `docs/**`), on pull
requests to `dev` and `main`, and on demand. The secret scan, the l10n guard and the check on
commit-message trailers exist only in the local hooks.

| Check | Command | Scope | PHP | Job |
|---|---|---|---|---|
| PHP syntax | `php -l` | all first-party PHP files | 8.0, 8.4 | `checks` |
| Conflict markers | `git grep` for `<<<<<<<` and `>>>>>>>` | PHP, JS, CSS and SCSS files | 8.4 | `checks` |
| Whitespace errors | `git diff --check` | changed PHP, JS, CSS and SCSS files | 8.4 | `checks` |
| Unit tests | `composer test:unit` | whole suite | 8.0, 8.4 | `checks` |
| PHPCS (errors only) | `.github/scripts/phpcs-changed.sh` | changed PHP, CSS and SCSS files | 8.4 | `checks` |
| PHPStan level 5 | `composer run lint:phpstan` | whole theme | 8.4 | `checks` |
| Integration tests | `composer test:integration` | whole suite, on WordPress 7.1.4 with ACF 6.8.10 and Polylang 3.9.1 and a throwaway MariaDB service | 8.4 | `integration` |

`composer.json` declares `config.platform.php` as `8.0.30`, so the lock file resolves on PHP 8.0
and 8.4 alike. `phpcs-changed.sh [<base>]` is also run by hand: the base is the commit before
the push or the tip of the target branch of a pull request, and without a valid base the files
of the last commit are checked. The `integration` job runs only on push to `dev` and `main`, on pull requests to `main` and on demand (not on the prefixed branches nor on pull requests to `dev`). WordPress (`wordpress-develop`, tag and commit checked), ACF and Polylang are pinned in the `env` of the job (the plugins through `DLI_ACF_VERSION` and `DLI_POLYLANG_VERSION`, see `tests/integration/README.md`); to update them, change those values on purpose. The job is new: its times and its false failures are being recorded in the private plan before it is considered stable.
